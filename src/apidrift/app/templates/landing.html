apidrift watches Stripe's published OpenAPI spec. When a release removes a field, retires an endpoint, or makes a new parameter required, it finds the call sites in your repository that send exactly that, and opens one issue with a link to each line. Nothing else: no digest of every change, no issue when you are unaffected.

Install on GitHub

Read access to code and permission to open issues; nothing else. apidrift downloads a snapshot of your default branch, reads it, and deletes it when the check ends. It never runs your code. It checks after each push to your default branch and whenever Stripe publishes a new spec.

How it works

  1. Stripe publishes spec3.sdk.json; apidrift keeps every version{% if stripe_latest %} (the latest it holds is {{ stripe_latest }}){% endif %}.
  2. Each release is diffed against the one your code last passed.
  3. Your Python, JavaScript, TypeScript and Ruby are parsed for Stripe calls and the fields they send. Only the calls the diff touches are reported.

What it does not do yet

  • No fix pull requests. That is next.
  • Stripe only.
  • It does not read which API version your account is pinned to.
  • Calls whose arguments it cannot see are marked ? (possibly affected), not guessed.
  • Other languages get endpoint-level matches from literal URLs only.
