Installed

apidrift checks each selected repository within a few minutes. If a Stripe release affects a repository, apidrift-check[bot] opens one issue in that repository's Issues tab, naming the release and linking to each affected line. Repositories that are clean get nothing.

When Stripe documents a replacement for what broke, an affected repository may also receive a pull request from apidrift-check[bot], on a branch named apidrift/stripe-<version>, with the change applied. It covers changes Stripe's changelog documents a replacement for: renamed fields, removed fields, and fields whose value changed shape (today: payment_method_types, payto, filters.countries, billing_cycle_anchor). Anything Stripe has not documented a replacement for (for example a new required field whose value only you know) still arrives as an issue. It is safe to close the pull request: apidrift never merges and never pushes to your default branch. If the installation has not accepted the write permissions, the issue gets one comment with the link to accept them instead.

A repository with Issues disabled is skipped; enable Issues to receive findings.

There is nothing to configure. The front page shows what a finding looks like. To uninstall, open github.com/settings/installations (or the organization's equivalent), choose apidrift, and uninstall.
