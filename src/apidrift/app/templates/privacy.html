Privacy

What is accessed

When a check runs, apidrift downloads a snapshot of the repository's default branch through the GitHub API and reads it. It also reads repository metadata (name, default branch, whether Issues are enabled) and creates, updates or closes one issue. When Stripe documents a replacement for a removed field, it writes exactly two things more: one branch named apidrift/stripe-<version> and one pull request per repository. It never writes to the default branch and never force-pushes over a branch a person has changed. apidrift asks GitHub for four permissions, as its consent screen labels them: Metadata: read (GitHub requires it of every App), Contents: read and write, Pull requests: read and write, and Issues: read and write. Nothing else.

The code is never executed. It is parsed for Stripe calls, and any fix is computed, in a separate process that holds no credentials; the snapshot is then deleted.

When Stripe publishes a release, apidrift does not download the code again. It asks GitHub which commit the default branch is at and compares the release with the index described below; a new download happens only when that commit has changed or the release changes what the repository's issue says.

What is stored

The repository's id and name, the number of Stripe call sites scanned, the number affected, a hash of the finding set, the issue number and, when a pull request was opened, its number, branch name, head commit and a hash of the fix set.

Also an index of the repository's Stripe call sites at the last commit checked, so that a new Stripe release can be checked without downloading the code again. For each call site it holds the file path and line number, the SDK call or Stripe URL as it is written there, the endpoint it reaches, and the names of the request fields it sends (names only, not values). With it are kept the commit id, the names the reader looked up in Stripe's API description to tell which calls are Stripe's (the last few names of a call such as stripe.charges.create, Stripe URLs, and in Go the names of struct fields passed to Stripe), including those that matched nothing, and, for each file that has a call site, one-way hashes of the property names read in that file (they tell whether a response field Stripe removes is used).

Never source files, never the values your code sends to Stripe, never secrets or tokens: an installation token is held in memory for one check or one lookup, is never written to disk, and is not logged. Logs contain repository ids only, not names, paths or code.

Where it runs

The server at {{ host }} is a single DigitalOcean droplet. Snapshots of repositories live on its disk only for the duration of a check; the index lives in its database.

When it is deleted

The snapshot is deleted at the end of every check, whether the check succeeded or failed. A repository's index is replaced each time the repository is checked and deleted when the repository is removed from the installation. Everything the server at {{ host }} holds for an installation, the index included, is deleted when the App is uninstalled.

How to uninstall

In GitHub, open Settings, Applications (or the organization's settings), choose apidrift, and uninstall. Nothing else is needed.
