Privacy

What is accessed

When a check runs, apidrift downloads a snapshot of the repository's default branch through the GitHub API and reads it. It also reads repository metadata (name, default branch, whether Issues are enabled) and creates, updates or closes one issue. apidrift asks GitHub for three permissions, as its consent screen labels them: Metadata: read (GitHub requires it of every App), Contents: read, and Issues: read and write. Nothing else.

The code is never executed. It is parsed for Stripe calls in a separate process that holds no credentials, then deleted.

What is stored

The repository's id and name, the number of Stripe call sites scanned, the number affected, a hash of the finding set, and the issue number. Never file paths, never source code, never tokens: an installation token is held in memory for one check, is never written to disk, and is not logged. Logs contain repository ids only, not names, paths or code.

Where it runs

The server at {{ host }} is a single DigitalOcean droplet. Snapshots of repositories live on its disk only for the duration of a check.

When it is deleted

The snapshot is deleted at the end of every check, whether the check succeeded or failed. Everything the server at {{ host }} holds for an installation is deleted when the App is uninstalled.

How to uninstall

In GitHub, open Settings, Applications (or the organization's settings), choose apidrift, and uninstall. Nothing else is needed.
